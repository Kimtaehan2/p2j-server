# DB 마이그레이션 정책

담당: 박영준(설계) · 김태한(운영). 모델과 마이그레이션은 **두 사람이 함께 리뷰**한다.

## 도구

**Alembic 만 사용한다.** (`0003-fastapi.md` 로 Prisma Migrate 는 폐기)

모델은 `app/db/models/`, 마이그레이션은 `alembic/versions/`. 두 곳이 어긋나면 CI 의 `alembic check` 가 실패한다.

## 현재 상태

`users`, `refresh_tokens` 두 테이블과 최초 마이그레이션(`0001_users_refresh_tokens`)이 있다.
JWT 골격이 참조하는 최소 범위다. 나머지 ERD v1 테이블은 **2주차 ERD 확정 후** 추가한다.

## 로컬 작업 순서

```bash
docker compose up -d                                   # PostgreSQL 16 + Redis 7
uv run alembic upgrade head                            # 현재 head 까지 적용

# 1. app/db/models/ 에 모델을 추가·수정하고 app/db/models/__init__.py 에 import 를 넣는다
# 2. 마이그레이션 생성
uv run alembic revision --autogenerate -m "add goals"
# 3. alembic/versions/<새 파일>.py 를 눈으로 읽는다  ← 건너뛰지 않는다
# 4. 적용
uv run alembic upgrade head
# 5. 모델과 DB 가 일치하는지
uv run alembic check
```

DB 없이 SQL 만 보려면: `uv run alembic upgrade head --sql`

## autogenerate 가 놓치는 것 — 직접 써 넣는다

Alembic 은 아래를 **감지하지 못하거나 이름을 잘못 만든다.** 생성된 파일에 손으로 추가한다.

```python
# 부분 유니크: 탈퇴 후 재가입 허용, 중복 가입 차단
op.create_index(
    "uq_group_active_member", "group_members", ["group_id", "user_id"],
    unique=True, postgresql_where=sa.text("left_at IS NULL"),
)

# 반복 목표는 빈도 필수
op.create_check_constraint(
    "frequency", "goals",
    "type = 'single' OR (frequency_times IS NOT NULL AND frequency_per IS NOT NULL)",
)
op.create_check_constraint("date_order", "goals", "end_date IS NULL OR end_date >= start_date")

# 부분 인덱스 (soft delete 제외)
op.create_index(
    "idx_todo_user_date_alive", "todos", ["user_id", "date"],
    postgresql_where=sa.text("deleted_at IS NULL"),
)
```

- CHECK 이름은 `naming_convention` 이 `ck_<table>_` 접두를 붙인다. `name="frequency"` → `ck_goals_frequency`.
- 모델 쪽에도 같은 제약을 `__table_args__` 에 적어 두어야 `alembic check` 가 통과한다.
- PostgreSQL ENUM 타입은 `downgrade()` 에서 `sa.Enum(...).drop()` 을 직접 호출해야 지워진다.
- `server_default` 변경, 컬럼 타입 변경은 `compare_type=True`, `compare_server_default=True` 로 감지하지만 **결과를 반드시 확인**한다.

## 금지 사항

- **병합·적용된 마이그레이션을 수정하거나 삭제하지 않는다.** 되돌려야 하면 새 마이그레이션을 추가한다.
- **`Base.metadata.create_all()` 을 운영·공유 DB 에 쓰지 않는다.** 테스트(SQLite)에서만 쓴다. 이력이 남지 않는다.
- **`docker compose down -v` 를 쓰지 않는다.** named volume 이 지워져 팀 공용 개발 데이터가 날아간다.
- 운영 DB 에 로컬에서 직접 붙지 않는다.
- `alembic.ini` 에 한국어를 쓰지 않는다 (OS 로캘로 읽혀 한국어 Windows 에서 깨진다).

## 운영 배포

Railway `Procfile`:

```
release: uv run alembic upgrade head
web: uv run uvicorn app.main:app --host 0.0.0.0 --port $PORT --workers 2
```

`release` 가 실패하면 새 버전이 뜨지 않는다. 마이그레이션이 안전한지는 로컬과 CI 에서 먼저 확인한다.

## PK 타입

ERD 의 `bigserial` 을 그대로 쓴다 — `BIGINT GENERATED BY DEFAULT AS IDENTITY`.
(NestJS 시절 "Prisma BigInt 가 JSON 직렬화에서 죽는다"는 이유로 `Int` 로 낮췼던 결정은 Python 에서는 해당 없다.)
모델에서는 `app/db/base.py` 의 `BigIntPK` 를 쓴다. SQLite 테스트에서 autoincrement 가 되도록 variant 가 걸려 있다.
